> 범위: 사용자가 "국가 추가 (5단계)"를 선택. 기획서 4장의 5단계 완료 기준 = **체르노보그 사태 → 용문 국지전 시나리오 성립**.

## 0. 공통 규칙 (모든 에이전트)

- 2단계 사양서(`docs/사양서_2단계_3국.md`) 0장의 공통 규칙을 그대로 따른다: 한국어·영어 로컬라이제이션 동시 작성(`l_korean`/`l_english`, UTF-8 BOM), 스크립트 파일은 ASCII, 키 접두사 `TU_<TAG>_`, 바닐라 기능만 사용(DLC 필요 기능 금지), 린트 `python -I tools\lint\tu_lint.py` errors=0.
- **이미 확인된 함정 (반드시 지킬 것)**
  - 국가 존재 확인은 `country_exists = TAG` (`exists = TAG`는 오류).
  - 전역 event_target 금지. 주는 **숫자 id**로 직접 스코프한다(`41 = { ... }`). id는 `common/scripted_effects/tu_generated_states.txt` 머리말(`# 이름 = id`)에서 읽는다.
  - 아이디어 `picture =`에는 `GFX_idea_` 접두사를 붙이지 않는다(`picture = generic_secret_police`). 중점 `icon =`은 전체 GFX 이름.
  - BoP는 `common/bop`에 정의하고, 국가 히스토리(`tools/mapgen/country_history/<TAG>.txt`)에 `set_power_balance = { id = ... set_default = yes }`, side마다 바닐라 `icon =`.
  - 기간이 있는 효과는 미션이 아니라 `days_remove` + `remove_effect`.
  - 중점 좌표: 같은 줄(y)에서 x 간격 2 이상(린트 C3가 검사).
  - 한국어 파일을 PowerShell Get-Content/Set-Content로 왕복하지 말 것(Edit/Write 또는 Python 사용).
  - 게임은 실행하지 않는다(실행·스크린샷은 Opus가 한다).
- 국가 태그: 염국 `YAN`, 빅토리아 `VIC`(이미 껍데기 존재) / **새 태그** 용문 `LGM`, 리유니온 `REU`.

### 에이전트 간 연결 규약
1. 태그·이름은 A가 `countries.json`에 넣은 것을 쓴다: `LGM` = 용문 / Lungmen, `REU` = 리유니온 / Reunion.
2. 주 id: A가 빌드 후 보고하는 표를 쓴다. 기존 id(체르노보그 41, 로도스 시작 정박지 215 등)는 **바뀌면 안 된다**(A가 보장).
3. 용문 수도 주 = 이름 `lungmen` (A가 만든 named state). B·D는 숫자 id로 참조.
4. 국가 플래그(이벤트 간 연결용, D가 설정하고 B가 읽을 수 있음): 전역 플래그 `TU_chernobog_incident_started`, `TU_chernobog_incident_resolved`, `TU_lungmen_border_conflict`, `TU_lungmen_survived`.
5. 캐릭터 id 접두사 `TU_<TAG>_`. 초상화는 바닐라 GFX(예: `GFX_Portrait_Europe_Generic_1` … 바닐라 interface에 정의된 것만, A의 validate 규칙과 같음).

## A. 지도·태그 확장 (먼저 단독 실행)

### A.1 용문 (`LGM`)
- `countries.json`에 추가: tag LGM, name_ko "용문", name_en "Lungmen", adj_ko "용문의", adj_en "Lungmenite", color [90, 140, 200], `custom_characters: true`.
- `regions.json` named_states에 추가: name `lungmen`, owner LGM, capital_of LGM, category `city`, manpower 60000, infrastructure 4, victory_points 15, **게임 좌표 x=2130, y=1880** (염국 서부, 육지). 프로빈스 1개짜리 주(원작 "단일 프로빈스 무역 허브").
- 용문은 다각형 영역이 없는 국가다. 생성기가 "영역 없음 + named state만 있음"을 허용하도록 고친다.

### A.2 리유니온 (`REU`)
- `countries.json`에 추가: tag REU, name_ko "리유니온", name_en "Reunion", adj_ko "리유니온의", adj_en "Reunion", color [110, 20, 30], `custom_characters: true`, 새 필드 `"dynamic": true`.
- dynamic 국가는 시작 시 주가 없다. 다각형·named state 없음. build_countries는 국가 정의·깃발·이름·히스토리 파일은 만들되 `capital =`에 체르노보그 주 id(41)를 쓰고, 소유 주는 없다. validate는 dynamic 국가의 "주 없음"을 오류로 보지 않는다.

### A.3 id 안정성 (가장 중요)
- 새 named state를 넣어도 **기존 주 id가 바뀌지 않아야 한다**. 새 주는 기존 번호 뒤(최대 id+1 이후)에 붙이는 방식으로 구현한다.
- `tools/mapgen/terra/pinned_ids.json`을 새로 만들어 기존 named state·anchor의 주 id와 대표 프로빈스 id(215/1053, 41, 58, 64, 앵커 9곳)를 기록하고, validate가 빌드 결과와 비교해 다르면 오류를 낸다.
- 튜토리얼 리맵(215/1053)과 손으로 쓴 스크립트(`41 = {`)가 이 id에 기대고 있다.

### A.4 검증·보고
- `python -I tools\mapgen\terra\build_terra.py` → BUILD_TERRA ok, `python -I tools\vanilla_cleanup.py` → VANILLA_CLEANUP ok, 린트 errors=0.
- 보고: 새 주 id(lungmen), 프로빈스 id, 기존 id 변동 없음 확인, LGM·REU가 국가 선택 화면용 bookmark에 들어가는지(REU는 넣지 않음, LGM은 넣지 않아도 됨 — 기존 bookmark 규칙 유지).

- 지도자: `TU_YAN_emperor` (이름 "염국 황제" / "Emperor of Yan"), neutrality(despotism 하위 이념 `despotism`).
- 장군·고문(캐릭터 파일): 종예 `TU_YAN_chongyue`(육군 장군, skill 4), 니엔 `TU_YAN_nian`(정치 고문 — 산업 계열 trait 바닐라 `captain_of_industry` 등 바닐라 존재 trait만), 시 `TU_YAN_dusk`(정치 고문, 선전 계열), 링 `TU_YAN_ling`(정치 고문, 안정도 계열), 웨이옌우 `TU_YAN_wei_yenwu`는 **용문 소속**이므로 LGM 파일에.
- 아이디어 3개: `TU_YAN_sleeping_giant`(산업 생산 -10%, 인력 +5%), `TU_YAN_imperial_bureaucracy`(정치력 +0.1, 안정도 +5%), `TU_YAN_sui_legacy`(초기에는 숨김 조건 없이 보유, 연구 +3%).
