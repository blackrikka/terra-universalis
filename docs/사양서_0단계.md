# 0단계 구현 사양서 — 기반 세팅

> 작성: Opus 5.5 · 구현: Haiku 5.5 (`haiku-implementer`) · 검증: Opus 5.5

## 조사 결과 (Opus)

- **BoP는 기본 게임 기능이다.** 바닐라 `history/countries/DEN - Denmark.txt`는 DLC 분기 **바깥에서** `set_power_balance`를 호출한다. 로도스(아미야↔닥터)와 라이타니엔(쌍둥이 여황제)에 그대로 쓸 수 있다.
- 로컬라이제이션 파일은 **UTF-8 BOM(EF BB BF)**으로 시작하고, 첫 줄은 `l_korean:` 또는 `l_english:`이다. 파일명은 `*_l_korean.yml` / `*_l_english.yml`이다.
- Python 3.10.7 사용 가능 (`python`).

## 전체 규칙 (모든 단계 공통)

1. 모드가 추가하는 모든 식별자(이벤트 네임스페이스, 디시전, 중점, 변수, 아이디어, GFX, 로컬라이제이션 키)는 접두사 `TU_`를 붙인다. 국가 고유 항목은 `TU_<TAG>_`로 쓴다.
2. 스크립트 파일(`.txt`, `.gui`, `.gfx`)은 **ASCII만** 쓴다. 한글은 로컬라이제이션 파일에만 넣는다.
3. 로컬라이제이션 키는 항상 `korean`과 `english`에 **같이** 추가한다.
4. 모드 파일명은 `tu_` 접두사를 붙인 소문자 snake_case로 한다 (바닐라 파일을 덮어쓸 때만 예외).
5. 들여쓰기는 탭, 줄바꿈은 LF와 CRLF 둘 다 허용한다.

### 4. 린트 도구 `tools/lint/tu_lint.py`

- Python 3.10 표준 라이브러리만 사용한다.
- 사용법: `python -I tools/lint/tu_lint.py [모드 루트]`. 모드 루트 기본값은 스크립트 위치 기준 `../../terra_universalis`이다.
- 출력은 한 줄에 하나씩 `ERROR <상대경로>:<줄> <메시지>` / `WARN ...` 형식으로 쓰고, 마지막 줄에 `TU_LINT errors=N warnings=M`을 쓴다. 오류가 있으면 종료 코드 1, 없으면 0이다.

**검사 A — 스크립트 파일** (`common/`, `history/`, `events/`, `interface/`, `map/` 아래의 `.txt`, `.gui`, `.gfx`. 단 `map/` 아래의 `.csv`와 `.bmp`는 제외):
- A1 중괄호 균형: 주석(`#`부터 줄 끝까지)과 큰따옴표 문자열 안의 중괄호는 무시한다. 닫는 중괄호가 남으면 그 줄에서 ERROR, 파일 끝에서 열린 중괄호가 남으면 마지막으로 열린 줄에서 ERROR를 낸다.
- A2 비ASCII 문자: 주석 밖에 있으면 WARN을 낸다 (위치 줄 포함).
- A3 UTF-8로 디코딩이 안 되면 ERROR를 낸다.

**검사 B — 로컬라이제이션** (`localisation/**/*.yml`):
- B1 파일명 접미사가 `_l_<언어>.yml`이고, 그 언어가 상위 폴더 이름(`korean`/`english`)과 일치해야 한다. 아니면 ERROR. `replace` 하위 폴더도 같은 규칙을 적용한다.
- B2 파일이 BOM으로 시작하지 않으면 ERROR.
- B3 첫 번째 비어 있지 않고 주석도 아닌 줄이 `l_<언어>:`가 아니면 ERROR.
- B4 항목 줄 형식은 정규식 `^\s+([A-Za-z0-9_.\-]+):\d*\s+"(.*)"\s*(#.*)?$`로 검사한다. 빈 줄, `#` 주석 줄, 헤더 줄이 아닌데 형식이 맞지 않으면 ERROR.
- B5 같은 언어 안에서 키가 중복되면 ERROR (두 위치 모두 표시).
- B6 korean과 english의 키 집합이 서로 다르면, 한쪽에만 있는 키마다 ERROR (`missing in english: KEY (korean/tu_core_l_korean.yml:3)` 형식).

**`--selftest` 옵션:** 임시 폴더에 정상 모드 1개와 위반 사례(A1 닫는 괄호 과다, A1 미닫힘, B2 BOM 없음, B3 헤더 오류, B4 따옴표 누락, B5 중복, B6 영어 누락)를 만든다. 각 사례가 해당 오류를 내는지, 정상 모드는 오류 0인지 확인하고 `SELFTEST ok`/`SELFTEST FAIL <사례>`를 출력한다.

## 완료 기준 (Opus가 검증)

1. `python -I tools/lint/tu_lint.py --selftest` → `SELFTEST ok`
2. `python -I tools/lint/tu_lint.py` → `errors=0 warnings=0`
3. 로컬라이제이션 파일 첫 3바이트가 `EF BB BF`
4. Documents의 다른 `.mod` 파일은 변경 없음
5. (사용자 승인 후) 게임 실행 → 런처에 모드가 보이고, 모드를 켠 채로 메인 메뉴까지 로드되며, `error.log`에 모드 관련 오류가 없음
